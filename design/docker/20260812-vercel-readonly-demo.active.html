在 Vercel 发布无持久化只读 Talebook 演示站

以仓库分支为版本源，在 Vercel Container Function 中运行完整 Talebook；实例只提供公开浏览、阅读和受限登录体验，所有运行期状态允许在休眠、扩缩容或重建后丢失。

状态：ACTIVE 创建日期：2026-08-12 所属模块：docker 影响范围：Vercel / Docker / Demo 配置 需求来源：用户对话

1. 原始诉求

“我要把 liaoshutian/talebook 仓库部署到 vercel 上面。”

经逐项确认：本次仅作 Demo，不要求持久存储；启用内置只读演示模式；工作分支为 deploy/vercel；先创建 Preview 部署，不直接修改 master 或生产环境。

2. 目标与边界

目标

  • 一个 URL 同时提供 Talebook SPA、Tornado API、阅读与下载能力。
  • 部署内容可追溯到 liaoshutian/talebook 的 deploy/vercel 分支。
  • 游客可浏览预置公版书，账号 demo / talebook 可体验只读管理界面。
  • 公开请求不能上传、编辑、删除、推送或持久修改系统设置。

非目标

  • 不保证书库、用户、Cookie、阅读进度或访问计数持久保存。
  • 不接入 Vercel Blob、外部数据库、对象存储或持久磁盘。
  • 不把本次 Preview 提升为生产部署，不配置自定义域名。
  • 不改变 Talebook 既有业务接口与只读演示策略。

4. 现状与证据

观察仓库或平台证据结论
Talebook 是 Calibre + Tornado + Nginx + Nuxt 的多进程应用Dockerfile、conf/supervisor/talebook.conf不能仅按普通 Nuxt 项目部署，否则 API 与阅读能力缺失。
业务数据默认写入 /data/bookswebserver/settings.py、docker/start.sh必须明确接受容器无状态和实例重置。
项目已有服务端只读演示策略webserver/demo_mode.py、tests/test_demo_mode.py复用既有能力，不新增另一套权限旁路。
Vercel 可从根目录 Dockerfile.vercel 构建 HTTP 容器Vercel Container Function 官方文档，2026-08-12 核对单容器可同时运行现有 Nginx 与 Tornado；默认入口端口为 80。

5. 方案

方案结论：新增根目录 Dockerfile.vercel。前端阶段从当前 Git revision 构建 Nuxt SPA；运行阶段复用固定 digest 的官方 Talebook 镜像中的 Calibre 与系统依赖，再覆盖当前 revision 的前后端代码和服务配置。最终以 scratch 阶段复制根文件系统，清除基础镜像继承的 /data OCI Volume 元数据，确保 Vercel 能在调用前创建只读根文件系统。固定 digest 避免运行依赖随 latest 漂移。
SOURCEGit 分支

deploy/vercel 保存容器入口、只读配置、测试与 ACTIVE 方案。

BUILD构建镜像

Nuxt SPA 使用仓库源码构建；Calibre 运行时复用发布镜像，覆盖当前后端代码。

BOOT绑定端口

Gateway 立即监听 0.0.0.0:80，首个请求在异步初始化完成前保持等待。

INIT初始化临时数据

Bootstrap 将预置书库复制到 /tmp/talebook/data，执行数据库迁移并启动 Tornado。

REQUEST同域服务

就绪后 Gateway 转发至 127.0.0.1:8081 的 Nginx；Nginx 提供 SPA 并代理 API。

vercel deploy . -y --no-wait
vercel inspect <preview-url>

6. 影响、风险与回滚

影响范围

新增 Vercel 专用 Dockerfile、只读种子配置、部署配置测试和本方案。普通 Dockerfile、Docker Compose、业务接口及默认配置保持不变。

回滚单位

删除 Vercel Preview 项目或回退 deploy/vercel 分支即可；无持久数据需要迁移或清理，master 不受影响。

主要风险：容器会缩容至零且无持久磁盘，因此并发实例的临时状态不共享，实例重建后登录会话与运行期修改会消失；该行为是本次 Demo 明确接受的产品边界。Demo 凭据和可分享 Preview 链接均是公开体验入口。
运行风险：镜像包含 Calibre，最终函数镜像为 393.08 MB；线上首次 API 冷启动实测约 9.4 秒。Vercel 运行时禁止写根文件系统和使用额外 Linux capabilities，因此所有运行期写入集中到 /tmp/talebook，Nginx 以 root 身份运行但没有附加 capabilities，隔离边界由 Vercel microVM 提供。
依赖风险：前端构建成功，但 npm 报告 42 个既有依赖漏洞（3 low、12 moderate、21 high、6 critical）以及大于 500 kB 的 chunk；本次部署适合作为短期 Demo，不据此宣称生产就绪。
